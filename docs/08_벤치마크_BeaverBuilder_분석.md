# 벤치마크 분석 · Beaver Builder → NanuriWeb 적용

> 2026-09-21 · 원칙: 코드·문구 복사 금지, **원리만 새로 구현**. Beaver Builder 는 대규모 SaaS(도구)이고 NanuriWeb 은 대행 서비스이므로, 그들의 얼굴을 흉내 내지 말고 그들이 잘하는 구조를 우리 신념 위에 다시 세운다.

---

## 1. 이 회사는 누구인가 (한 문단)

Beaver Builder 는 2014년 미국에서 시작한 WordPress 페이지 빌더 회사다. 자기 자신은 "코드를 몰라도 웹을 만들 수 있게 하는 도구"를 판매한다. 우리와 성격이 다르다 — 그들은 도구(연장)를 팔고, 우리는 완성품(작업 결과)을 팔고 관리한다. 그런데도 이 회사의 홈페이지 정보 구조·자기 학습 자원·대상자별 안내는 오래 다듬어진 것이라 원리만 뽑아 쓸 가치가 있다.

---

상단 메뉴 5개 대분류:

| 대분류 | 하위 | 방문자에게 주는 신호 |
|---|---|---|
| **Products** | Page Builder · Theme · Themer · Assistant Pro · Features · Modules · Pricing · Demo | "무엇을 파는지" 를 한 자리에 |

상단에 뉴스레터 CTA 한 줄: _"Build better WordPress sites — Tutorials, product news, and practical ideas."_

## 3. 우리가 배울 원리 (5개)

### 원리 1 · 정보 구조는 3초 안에 자기 자리를 찾게
5개 대분류가 명확하다. 방문자는 스크롤 없이 자기가 어느 문을 열어야 하는지 판단한다. 우리 nanuriweb.com 은 지금 하나의 긴 페이지에 모든 이야기가 섞여 있다. 대분류를 최소 3–5개로 나누면 담임목사님이 어디를 눌러야 할지 판단하기 쉬워진다.

### 원리 2 · Solutions 는 "대상자별로" 나눈다
Business Owners · Freelancers · Agencies — 대상마다 페이지가 따로 있다. 각 페이지가 그 대상의 언어와 관심사로 이야기한다. 우리에게는 **교회 · 사업체 · 기관** 이 그것이다. 지금은 한 카테고리 안에서 모두 이야기하지만, 각 대상 페이지를 짧게라도 따로 두면 "우리 이야기다" 라는 느낌이 급격히 강해진다.

### 원리 3 · Learn 은 자기 학습을 가능하게
Templates · Knowledge Base · Courses · Videos · Blog — 유료 고객이 아니어도 배울 수 있는 자원을 앞에 놓았다. 이것이 신뢰의 뿌리다. 우리에게는 **템플릿 미리보기 · 자주 묻는 질문 · 짧은 영상 3개 · 블로그 (교회 홈페이지 만드는 이야기)** 정도가 가능한 시작이다. 무료로 배울 수 있으면, 유료로도 맡긴다.

### 원리 4 · Success Stories + Showcase 를 나눈다
그들은 **Success Stories** (이야기 · 사람 중심) 와 **Showcase** (완성 결과 · 화면 중심) 를 별개로 갖는다. 우리는 지금 "제작사례" 하나에 두 성격이 섞여 있다. 나누면 각각의 자기 자리를 얻는다.
- 이야기: "에덴교회 · 시애틀지구촌교회 목회자 인터뷰 3분"
- 결과: "완성된 화면 10개 · 각 3–5장의 스크린샷"

### 원리 5 · 뉴스레터 CTA 를 상단에 놓는다
지금 방문했지만 계약할 때가 아닌 담임목사님이 나중에도 우리를 잊지 않도록. "환대의 홈페이지를 만드는 이야기 · 격주 1회" 정도의 낮은 부담 뉴스레터. 이메일 하나만 받으면 6개월 뒤 계약이 돌아온다.

## 4. 흉내 내지 말아야 할 것 (3개)

### 흉내 X · 대규모 커뮤니티(Forum · Slack · Discord)
그들은 수만 명 사용자가 있어 커뮤니티가 자연스럽게 움직인다. 우리가 지금 Discord 를 열면 빈 자리가 될 뿐이다. **이메일 문의 하나로 충분하다**. 커뮤니티는 사용자 100명이 넘어간 뒤에 생각한다.

### 흉내 X · 월 구독 SaaS 언어
그들은 "annual license · monthly plan · renewal" 언어를 쓴다. 우리 신념은 **"월 이용료로 잠기지 않는 구조 · 완성된 사이트는 교회 소유"** 다. 이 정체성을 흐리는 언어는 절대 쓰지 않는다.

### 흉내 X · 개발자·에이전시 언어
"Modules · Add-Ons · Integrations · API" — 그들의 대상은 개발자·프리랜서·에이전시다. 우리 대상은 **담임목사·이사·사무장** 이다. 우리는 "메뉴 · 예배 시간 · 목장 안내 · 관리자 화면" 같은 말을 쓴다. Beaver Builder 의 어휘를 그대로 옮기면 우리 손님이 문 앞에서 돌아간다.

### 제안 A · 상단 메뉴 재구성 (5 대분류)

| 지금 | 개선안 | 하위 |
|---|---|---|
| (한 페이지 스크롤) | **템플릿** | 교회 10종 · 사업체 10종(예정) · 기관 10종(예정) · 미리보기 갤러리 |
| | **대상별** | 교회 · 사업체 · 기관 (각 짧은 페이지) |

| | **제작사례** | 이야기 (사람) · 화면 (결과) |
| | **회사** | 우리 신념 · HebronGuide 연결 · 문의 |

### 제안 B · 대상별 페이지 세 장 (짧게)

각 페이지 구조 (한 화면 스크롤 두 번 정도):
1. 머리: "당신 같은 [교회 / 사업체 / 기관] 을 위한 홈페이지"
2. 이런 것을 만들어 드립니다 (3–4가지 대표 기능)
3. 이런 곳에 잘 맞습니다 (실제 예시)
4. 이 대상에게 적합한 디자인 3종 (미리보기 링크)
5. 세 상품 가격
6. [문의하기]

### 제안 C · 자료실 페이지 (Learn)

지금 이미 있는 자산으로 시작 가능:
- **자주 묻는 질문 15개**: `03_교회섹션_재구성안.md` 의 FAQ 세트 그대로 옮김
- **짧은 영상 3개** (촬영 필요): "관리자 화면에서 공지 올리기 · 사진 올리기 · 인사말 수정하기"
- **블로그 5편** (초안 필요): "교회 홈페이지 만들기 전 준비 · 미국 교회 법 4가지 · 목장 안내 페이지 원리 · 헌금 확인서 안내 · HebronGuide 자동 등재의 의미"
- **무료 체크리스트 PDF**: "우리 교회 홈페이지 준비 체크리스트 (한 장)" — 다운로드 = 이메일 수집 = 뉴스레터 리스트

### 제안 D · 뉴스레터 상단 CTA

지금 nanuriweb.com 최상단(포지셔닝 카피 근처)에 한 줄:
```
환대의 홈페이지를 만드는 이야기 · 격주 1회 · 이메일 하나면 충분합니다
[이메일 입력]  [구독하기]
```

### 제안 E · 제작사례 두 갈래로 분리
- **이야기**: 3분 이내 인터뷰 (담임목사·사무장) · "왜 새로 만들었는가 · 무엇이 좋아졌는가"
- **화면**: 실제 사이트 스크린샷 5장 (PC · 폰) + [사이트 방문 →]

## 6. 이 벤치마크가 우리에게 주는 큰 신호

Beaver Builder 의 강함은 **"손님이 스스로 배우고, 스스로 자기 자리를 찾고, 스스로 다음 걸음을 정할 수 있는 구조"** 다. 판매자가 밀지 않아도 판매가 일어난다.

우리도 같은 방향이다. 다만 우리는 **환대의 얼굴**로 그것을 한다. 밀지 않는다. 자기 자리를 찾아가시게 자리만 마련하고, 오시면 정성으로 맞이한다. 그리고 완성된 홈페이지는 **HebronGuide** 를 통해 이웃과 세계로 이어진다.

이 회사가 가르쳐 준 것은 **판매 언어가 아니라 안내 언어의 힘** 이다.
