# NanuriWeb 고객 유지보수 게시판 — 결정 메모 (2026-10-01)

목사님과 정한 내용. 설계 1부까지 진행, 목사님 확인 전에 NanuriWeb 프로젝트로 옮김.
배경 문서: `01_Hebron_Platform_LLC/NanuriWeb_왓에버서치_벤치마크_적용안.md` (4장 적용 원칙)

## 목적
NanuriWeb 고객(교회·사업체)이 수정 요청을 올리고, 처리 상태와 답변을 한곳에서 주고받는 창구.
왓에버서치 유지보수 게시판의 장점(요청별 상태·댓글 답변)은 가져오고, 불편(광고 글 섞임, 금액 숨김, 번거로운 해지)은 없앤다.
HebronGuide 정착 지원 요청에도 같은 흐름(접수 → 분류 → 처리 → 기록)을 쓸 수 있게, AI 협업의 첫 연습 무대로 삼는다.

## 설계 1부 — 고객 화면 (목사님 확인 전)
1. 들어오기: 코드 6자리
2. 목록: 최신순, 상태 · 완료 예정일 · "새 답변" 표시. 상태 5단계 = 접수 → 확인 중 → 작업 중 → 확인 부탁 → 완료. "진행 중 / 완료" 두 칸. 광고·공지 없음
3. 새 요청: 종류(글 수정 · 사진 교체 · 오류 신고 · 새 기능 · 기타), 제목, 내용, 페이지 주소(선택), 급한 정도(보통/급함), 첨부, 답변 받을 이메일(교회 기본값)
4. 자세히: 요청 + 첨부 + 댓글 대화. 댓글에도 첨부. "확인 부탁" 상태에서 "잘 됐습니다(완료)" 버튼, 7일 무응답이면 자동 완료
5. 원칙: Hebron 디자인 시스템(Pretendard · Geist), 큰 글씨, 누름 영역 44px, 휴대폰 우선, 한국어 기본 + 영어 전환, 이모지 금지

## 남은 설계
- 2부: 관리자(목사님) 화면 — 전체 고객 요청 보기, 상태·완료 예정일 바꾸기, 답변, 고객 코드 관리 / 이메일 알림 문구
- 3부: 시트 구조(고객 · 요청 · 댓글 · 코드), 보안(코드 범위 확인, 첨부 형식 제한), 오류 처리, 시험 방법
- 그다음: 설계서(spec) 작성 → 목사님 확인 → 작업 계획 → 제작 → 로컬 미리보기 → 배포 확인
