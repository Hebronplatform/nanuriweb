# handoff-package · 공개 뒤 인수인계 (공개 당일 혹은 다음 날)

> 버전: **1.0** (2026-10-02 확정) · 목사님 승인 완료
> 사용 방식: 매 사용 뒤 `notes.md` 에 기록 · 수정은 폴더에서 (채팅 X)

## 목적
공개된 사이트를 교회에 **온전히 넘겨 드린다**. 관리자 계정은 **안전한 채널**로, 자주 바꾸실 다섯 가지(공지·주보·사진·인사말·오시는 길)는 **짧은 영상 세 개**로, 사이트 자료 인계는 **서면 약속**으로. 한 달 뒤 저희가 먼저 **안부를 묻는다**.

## 언제 쓰는지 (실제로 치는 말)
- "OO교회 공개 됐으니 인수인계 보내줘"
- "핸드오프"
- "handoff"

## 입력
- 교회 이름 (한글·영문)
- 담임목사(또는 담당자) 호칭·성함·이메일
- 공개 완료 일시 (YYYY-MM-DD HH:mm)
- 사이트 도메인 (예: yourchurch.org)
- 관리자 계정 (아이디·임시 비밀번호 — **이 파일에는 쓰지 않음**)
- 사용된 디자인 번호 (10종 중)
- 호스팅·DNS 정보 (대부분 저희가 관리하지만, 교회가 넘겨받고 싶으시면 DNS·도메인 이관 패키지 포함)

입력이 빠지면: 추측하지 않고 담당자에게 먼저 확인. **관리자 계정은 다른 폴더에서도 평문으로 저장 금지**.

## 순서

1. 공개 완료 확인 — 사이트가 `https://` 로 열리는지, 모바일에서 잘리는 곳이 없는지, 검색 엔진 등록이 완료됐는지, **HebronGuide 자동 등재가 완료됐는지** 두 눈으로 확인.
2. `files/handoff-email.md` 자리표시자 채우기.
3. 관리자 계정은 `files/credential-transfer.md` 의 **안전 채널 방식** 으로 별도 전달 (이메일 평문 금지).
4. `files/admin-walkthrough-videos.md` 짧은 영상 3개 링크 삽입 (교회 유형별 맞춤 녹화가 필요할 수 있음).
5. `files/data-ownership-pledge.md` 서면 약속 문구 삽입.
6. `files/emergency-contact.md` 긴급 연락 안내 삽입.
7. `files/one-month-checkin.md` 1개월 뒤 체크인 — **달력에 즉시 등록** (D+30).
8. `files/tone-rules.md` 톤 검사.
9. **증명 항목 5개** 셀프 체크.
10. 모두 통과하면 송부. 목사님께 "핸드오프 완료 · D+30 체크인 등록 완료" 보고.

## 결정 규칙

| 상황 | 조정 |
|---|---|
| 교회가 **도메인·DNS 를 교회 쪽에서 관리**하길 원하심 | `credential-transfer.md` 의 "도메인 이관 패키지" 섹션 **포함** (Namecheap·Cloudflare 이관 EPP 코드) |
| 교회가 **자체 사무장·IT 담당**이 계심 | 짧은 영상 3개 외에 **긴 영상 1개** (관리자 화면 전체 투어 20분) 추가 녹화 |
| 교회가 **유지보수 계약 선택** | 긴급 연락 안내에 "저희가 매월 백업·업데이트 담당" 명시 |
| 교회가 **유지보수 미계약** (한 번만 결제) | 긴급 연락 안내에 "**30일 무상 사후 지원**" + 그 후 "건당 지원 가능 (시간당 $89)" 명시 |
| **공개 직후 사이트 다운 사고 발생** | 핸드오프 보류 · 사고 수습 → `notes.md` 에 사고 기록 → 수습 완료 후 핸드오프 재발송 |

## 완료의 정의
아래 증명 항목 5개가 **모두 통과**하면 송부한다.

## 증명 항목 (외부 증거로 확인 가능)
- [ ] **관리자 계정이 이메일 본문에 평문으로 있지 않은가** (ctrl+f: "비밀번호" "password" "pw" 모두 없음)
- [ ] **짧은 영상 3개 링크가 작동하는가** (브라우저에서 하나씩 열어 확인)
- [ ] **자료 인계 서면 약속이 포함되어 있는가** (ctrl+f: "교회 소유" · "인계")
- [ ] **긴급 연락처가 포함되어 있는가** (ctrl+f: 이메일 · 전화 · 응답 시간대)
- [ ] **D+30 체크인이 달력에 등록되어 있는가** (Google Calendar · Apple Calendar 중 어느 쪽이든 **실물 확인**)

두 개 이상 실패하면: 결과물을 고치지 말고 **프로세스가 왜 실패했는지** `notes.md` 에 기록 → 템플릿·전달 방식·영상·체크인 중 어느 것을 바꿀지 결정.

## 왜 이 스킬이 중요한가
공개는 **끝이 아니라 시작**이다. 교회가 "이제 뭘 해야 하지?" 라는 두 번째 불안을 안고 홀로 서지 않도록. 관리자 계정은 **보안 사고의 가장 흔한 창구**이므로, 평문 전달 한 번이 1년의 신뢰를 깬다. 그래서 이 폴더의 신념은 **"책임의 이양 + 자기 환대"** — 교회가 자기 사이트의 주인이 되시도록, 저희는 뒤에 선다.
